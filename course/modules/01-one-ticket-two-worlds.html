One Ticket, Two Worlds

Follow one angry customer email through an n8n drawing and through TypeScript code, and see that it is the same journey. This is an optional parity bonus, not Workshop 4's required lessons.

Meet Maarten, who was charged twice

This project takes a customer support message and decides how urgent it is. It was first built as an n8n workflow. This repository rebuilds it as an agent written in TypeScript.

📩

The ticket: WL-1026

"I was charged twice. I need this fixed today or I will file a complaint." (Maarten)

🏷️

The label

Priority high. Every ticket gets low, medium or high.

🚨

The route

High means escalate to the "Payments escalation team". Only as a draft.

🧭
The rule of this repo

The labels must not move. The same tickets must get the same low / medium / high answer in n8n and in the new agent. That promise lives in fixtures/expected-labels.json, separate from Workshop 4's support messages.

The drawing is secretly text

When you export an n8n workflow you get a JSON file. Every box on the canvas is one entry in a nodes list. Here is the Ticket Input station from n8n/support-triage.json.

n8n/support-triage.json 
{
  "parameters": {
    "mode": "raw",
    "jsonOutput": "{\n  \"ticket_id\": \"WL-1026\",\n  \"customer\": \"Maarten\",\n  \"message\": \"I was charged twice. I need this fixed today or I will file a complaint.\"\n}",
    "options": {}
  },
  "type": "n8n-nodes-base.set",
  "typeVersion": 3.4,
  "position": [
    16,
    -48
  ],
  "id": "8d055d43-cd0c-4aa1-8728-1879947aa62f",
  "name": "Ticket Input"
}
PLAIN ENGLISH

This is one box on the canvas.

Its settings: "raw" mode means "I will type the output by hand".

The ticket itself, squeezed into one string. The \n marks are line breaks and the \" marks are quotes that had to be escaped.

So the ticket is hard-coded inside the drawing. Every run triages Maarten.

"set" is the kind of box: it sets data.

The position numbers are only where the box sits on screen (x = 16, y = -48). They mean nothing to the logic.

A random unique id for the box.

The name you see on the canvas. Other boxes point to it by this name.

In the TypeScript version the same ticket is its own small file, fixtures/ticket.json, a fixture. The ticket is data you pass in, not something welded into the machine.

The same trip, written as a timetable

If n8n is the railway you can see, the TypeScript agent is the printed timetable: the same stops, written as text. You lose the pretty picture. You gain something you can search, compare line by line, and test.

1
Trigger → src/cli.ts

You type npm run triage -- fixtures/ticket.json --dry-run in a terminal.

2
Ticket Input → parseTicket()

The file is read and its shape is checked before anything else happens.

3
AI Agent → runTriage() in src/agent.ts

The model loop, with the Reply and Risk helpers as subagents.

4
Code in JavaScript → parseJson() + validateDecision()

Turn the model's text into data, then check it.

5
Switch + Action nodes → routeDecision()

A small lookup table picks the action and the team.

src/cli.ts 
  const inputPath = positionals[0] ?? "fixtures/ticket.json";
  const json = parseJson(await readFile(inputPath, "utf8"));
  const ticket = json.ok ? parseTicket(json.value) : json;
  if (!ticket.ok) {
    console.error(`FAIL input ${inputPath}\n  - ${ticket.errors.join("\n  - ")}`);
    return 1;
  }
PLAIN ENGLISH

Which ticket file? Whatever you typed after the command. If you typed nothing, use Maarten's ticket.

Read the file as text and try to turn it into data.

If that worked, check it really looks like a ticket. If not, keep the error.

Something is wrong with the input...

...so print every problem, one per line, starting with FAIL...

...and stop with exit code 1 ("failed"). The AI model is never called.

End of the check.

💡
Pictures versus text

A visual tool is great for seeing a flow. Text is great for diffing, reviewing and testing. This repo even has a test (test/n8n-source.test.ts) that reads the n8n JSON and checks its wiring, so the drawing can't change without someone noticing.
